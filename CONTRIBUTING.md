## Release process and versioning

### Version numbering

This repository follows [Semantic Versioning](https://semver.org/) (MAJOR.MINOR.PATCH):

- **Repository-level version**: Tracked in `CHANGELOG.md` (e.g., `0.1.0`)
- **Skill set version**: For skill sets like `jw-agenda`, the version matches the repository version
- **Individual skill version**: Each skill’s `SKILL.md` metadata includes a `version` field (e.g., `version: "0.1.0"`)

**Version alignment**: When releasing a new version:
1. Update `CHANGELOG.md` with the new version and changes
2. Update all skill `SKILL.md` metadata `version` fields to match
3. Update skill set-level version (if applicable) to match

### Release process

When creating a GitHub Release:

1. **Version tag**: Create a Git tag matching the version (e.g., `v0.1.0`)
2. **CHANGELOG summary**: Include a summary from `CHANGELOG.md` in the release notes
3. **Distribution files**: Attach distribution files:
   - **Option A (recommended)**: 5 separate zip files (one per skill), generated by running `./jw-agenda/package-skills.sh` in the `jw-agenda/` directory
   - **Option B**: One bundled zip containing all skills (if preferred for bulk distribution)
4. **Release notes**: Include:
   - What changed (from CHANGELOG)
   - Installation instructions (link to README)
   - Breaking changes (if any)

### Example release workflow

```bash
# 1. Update CHANGELOG.md with new version
# 2. Update all skill SKILL.md version fields
# 3. Commit changes
git add CHANGELOG.md jw-agenda/skills/*/SKILL.md
git commit -m "chore: bump version to 0.2.0"

# 4. Create tag
git tag -a v0.2.0 -m "Release v0.2.0"

# 5. Generate distribution zips (for jw-agenda)
cd jw-agenda
./package-skills.sh
cd ..

# 6. Push tag
git push origin v0.2.0

# 7. Create GitHub Release via web UI, attach zips from jw-agenda/output/
```
