# 模式：添加/移动任务

处理用户添加新任务或移动现有任务到目标日期。

> **额外加载**：`assets/conventions-marks.md` + `assets/conventions-cascade.md`。

## 触发

「加一项 XXX」「明天要 XXX」「把 X 移到周三」「推迟到 2.10」「记一下 XXX」「本周三要 XXX」「本月要 XXX」「以后要 XXX」等。

## Step 1: 识别任务与目标日期

从用户输入提取：**任务内容**、**目标日期**（今天/明天/本周X/本月/下周/某日/以后）。若未指定日期，默认今天。若有歧义先推算具体日期，必要时向用户确认。

根据目标日期决定写入哪些文件（依次写入，从大粒度到小粒度）：

| 时间范围 | 写入文件 |
|----------|---------|
| **无法确定日期** / **不是当月会做的事** | `{agendaRoot}/tasks/TODO.md` |
| 今天 / 明天 / 本周某天 | ① `{agendaRoot}/monthly/YYYY-MM-plan.md` → ② `{agendaRoot}/weekly/Week{W}-plan.md` → ③ `{agendaRoot}/daily/YYYY-MM-DD-todo.md` |
| 本周（无具体日） / 下周 / 某周 | ① `{agendaRoot}/monthly/YYYY-MM-plan.md` → ② `{agendaRoot}/weekly/Week{W}-plan.md` |
| 本月 / 以后（更远） | `{agendaRoot}/monthly/YYYY-MM-plan.md` |

## Step 2: 判断是移动还是新增

检查今日 todo 中是否存在相同或相似任务（归一化比较，忽略标记和空格）：
- **存在**：视为移动，记录原日期（今天）
- **不存在**：视为新增

## Step 3: 更新源日期（仅移动时）

若为移动，在今日 todo 中删除该条目。

## Step 4: 更新目标日期

- 若目标日 todo 存在：幂等检查后追加
- 若不存在：创建仅含此项的文件（建议立即创建以保持一致性）
- **标记**：
  - 移动：`*(从 M.D 移入)*`（M.D 为原日期，如 `2.5` 表示 2 月 5 日）
  - 新增：`*(临时追加)*`

## Step 5: 从上往下级联同步规划文件

**核心原则**：每次调整任务后，**必须从上往下逐层检查**，确保各层规划保持一致。不可只改日计划而忽略上层规划文件。

按 conventions-cascade.md「从上往下级联同步标准步骤」执行，本模式特定行为：

- **5a tasks/TODO.md**：若任务来自总待办且已安排到具体日期 → 标记已规划或移除；新增无明确日期的任务 → 写入总待办；任务取消 → 相应标记
- **5d 日计划**：已在 Step 3–4 中处理（更新源日期 todo 和目标日期 todo），此处跳过

## Step 6: 汇报

说明操作类型（移动/新增）、目标日期、已同步的文件。**必须列出所有修改过的文件路径**（如 `{agendaRoot}/tasks/TODO.md`、`{agendaRoot}/monthly/...`、`{agendaRoot}/weekly/...`、`{agendaRoot}/daily/{日期}-todo.md`），让用户知道改动落在哪些文件。

## 错误处理

通用默认策略见 `assets/conventions.md`「错误处理默认策略」。以下为本模式特定情况：

| 情况 | 处理 |
|------|------|
| 目标文件不存在 | 自动创建仅含此项的新文件，向用户说明已创建路径 |
| 源任务找不到（移动时） | 提示用户任务在今日 todo 中未找到，询问是否改为新增，或提供其他源日期 |
| 跨月边界（目标日期跨入下月） | 正常处理，更新目标月的月规划（`YYYY-MM-plan.md`）而非当前月 |
| 跨年边界（目标日期跨入下一年） | 正常处理，同时更新目标年的周规划和月规划；若涉及年规划（`YYYY-plan.md`）则同步检查 |
